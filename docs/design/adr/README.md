# Architecture Decision Records

One decision per file (MADR-lite: decision · why/rejected-alternative · consequences). The *why*,
especially the rejected alternative, is the load-bearing part — it's what decays from memory.

## Citing code from an ADR

**An ADR that quotes `file:line` names the commit it was written against**, as a header:

> **Verified against `052895c` (2026-07-22).**

A citation pinned to a commit **cannot rot** — it was either right at that commit or never right —
so the ADR stays readable years later instead of decaying the moment the next PR lands. Without the
pin, the honest repair for a paragraph describing older code is to *delete* its line numbers rather
than repoint them into a file that no longer supports the sentence (which is what ADR-0040's
baseline section needed in PR #408).

Use a **git hex id while the code is churning** — during 0.7.0 the code mutates faster than the
version tags, so a release tag would predate half the files an ADR cites. Once the churn settles, a
**release tag is the more valuable pin**: it is immutable, meaningful to a reader, and survives in a
shallow clone.

Two things worth knowing:

- **Name the symbol next to the citation** — write the symbol first and the location after it, never
  a bare line number. In this codebase the line number is the part that rots: every stale citation
  measured on 2026-07-22 was the symbol sitting still in its file while its line drifted. The file
  and the symbol are what a reader can recover from; the number is a convenience. (This bullet
  deliberately carries no `path:line` of its own — an example here would be a live claim, and would
  be stale within the week.)
- **Re-pin when you amend.** A header naming an old commit says nothing about a section added later,
  and a citation added under a stale pin is verified against the wrong tree.

- [0042](0042-inherited-node-edit-gesture.md) — **The edit gesture on an inherited node: two bounded axes, one rule.** A **layer picker** docked in the editor *header* (not the rail — the rail collapses, and body/title write to L too) is the hierarchy axis's counterpart to 0013's foot-docked manuscript scrubber, and *position is the mode* on both. The **authoring layer L is bounded** (`node's owning layer ≤ L ≤ open project`): at the owning layer an ordinary write, below it an `overrides/` delta — so direct-edit and override are **one write at two positions**, and only `⧉` fork stays a button. The bound is on the **write target only**; every picker still resolves `base → L`, so truncation drops the layers *below* L (whence "a name is asserted at or above the layer holding the value that uses it", free). ## 0.8.0 — Remaining features
- [0043](0043-scene-snapshots-are-witnesses.md) — **Scene snapshots are witnesses**: a fully correct snapshot of a scene is **not constructible** (mutation intervals span scenes — a scene inside an interval it does not own carries no markers yet its meaning is set elsewhere; manuscript order lives in another file; ADR-0039 adds a second drift axis through the layer chain), so the feature accepts that instead of defeating it — **prose is restored byte-exact, context is captured and only reported when it has drifted**. Witness = `effective_state` output + a per-entity change token (#314's composite revision is the inheritance-axis detector); diagnostic only, never restored, never read by the resolver, preserving the derived-never-stored rule (0010). **Scenes only in v1** (lore entries are the drift *targets* and become composed values under 0039). **Full copies, not deltas** — plain text buys the diff *view*, it does not oblige delta *storage*. Two triggers with asymmetric retention: lazy session-boundary capture (materialized only if the session dirties the doc, **keep last 5** — the automatic tier is a prosthetic for the author's own recall, and that is roughly the depth a person holds) + an explicit Scrivener-style button (**never thinned**). **Identity:** a snapshot carries its **own id**, never the source's (the front-matter id is canonical and 0040's index maps `id → candidates by layer` — reusing it is an index collision); stored as **two files**, a byte-for-byte copy of the scene plus a sidecar (`id`, `snapshot_of`, `captured_at`, `retention: thinned|kept`, capture-time `schema_version`, the witness — and deliberately **no** denormalized `title`: the copy's front matter already has it, so duplicating it would be a denormalization with no consumer that exists), so byte-exactness is *proven by file copy, not reconstructed through a serializer*. **The directory layout `snapshots/<source-id>/` IS the lookup table** — "how many/which" is a listing, no index to invalidate (an index only when a query the filesystem can't answer cheaply exists); deliberately makes a *directory* name load-bearing where filenames are cosmetic, since ids are stable and titles are not. **Invariant: `snapshots/` is excluded from the node index once, at the index** — not filtered per consumer, or every scene view gains 5× members. **Deleting a scene deletes its snapshots**, count named in the confirmation — an earlier draft retained them, which was wrong because **unreachable data is not preserved data**: the directory is named by id, the author knows scenes by title, and with no node left to hang an affordance on, retention without a recovery surface is disk usage plus a false sense of safety (the worst of the three options, being the one that *looks* safe). Recovery is out of scope — it belongs to a general undelete, not one per feature — and deleting also keeps snapshots from becoming the only soft-delete-ish thing in an app whose deletes are all `path.unlink()`. Durable property either way: **a scene and its snapshots are one unit of deletion**, which would still hold under a future trash metaphor (whether snapshots participate is that design's call, not committed here). Names the two live collisions the feature must dodge (`revision` = the transient sha256 concurrency token; "time travel" = 0013's in-fiction scrubber). Rejected: per-save snapshots (autosave's 6 s debounce makes the boundary meaningless), git-style history (no git anywhere in the codebase), whole-project checkpoints (self-consistent but makes losing unrelated work the default failure mode). **Drift reporting is advisory, never blocking** — a tool, not a straitjacket; the binding obligation is that the report name the *specific* change in the author's vocabulary, since it is then the only protection (a vague warning trains dismissal). **Not blocked on #314**: `revision` is consumed as an opaque change token, so 0039's composite hash improves the detector with no change here (pre-#314 tokens report the inheritance axis as *unknown*, not *unchanged*). Sequencing is governed by **file contention, not dependency** — backend near-disjoint, surface should follow the 0042 editor rework. User-facing surface deliberately **not** designed here → **ADR-0044**. The ADR was **held open until that UX pass** rather than merely unreviewed (three of its load-bearing decisions arrived as *how would this be used?* questions), and **the prior held**: the pass returned three additions, now **Amendment 1** — a snapshot can be **deleted** (immutability means a migration never rewrites one at rest, NOT undeletable — and full copies make deletion safe where deltas would need a chain repair); a snapshot can be **pinned** (`thinned`→`kept`, the enum's third case); and **restore captures first**, so it is undoable by construction rather than by the author's foresight — which is what actually justifies advisory-not-blocking, and sharpens the split (restore reversible → no gate; delete irreversible → confirm). Side effect stated, not left to be discovered: the auto-capture is `thinned`, so restoring on a full scene evicts the oldest. Sidecar gains an optional one-line **`description`** — original data, unlike the removed denormalized `title`. **No implementation starts until 0043 AND 0044 are approved.** **The third drift axis is value *reinterpretation*, not schema change** — invisible to both other detectors (`_revision` hashes the entity file; the schema is a separate merged file), but far narrower than "the schema changed": stored files are **sparse**, so an added field is simply absent and a deleted one is stripped, needing no detector. Only a type change or a shrunk option set makes surviving bytes mean something new, so the token covers the type/constraints of **the fields the witness recorded**, not the merged schema (a whole-schema hash was drafted and rejected: it fires on harmless edits, and under an advisory model a detector that cries wolf trains the dismissal that makes the report worthless — **detector precision is part of the report-quality obligation**). **Snapshots are irreplaceable-but-not-authoritative** — a category the project has not had: unlike `.cache/` (rebuildable) and `.migration-backups/` (disposable), the pre-1.0 "bump the key and rebuild" escape hatch does **not** apply, so a pre-1.0 store must stay readable after 1.0. **Snapshots are immutable — migration happens at restore, not at rest** (rewriting a witness destroys it), which yields the free result that they need no migration backup, and imposes a **hard pre-1.0 requirement on the migration framework**: content migrations must be expressible as per-document functions, which `MigrationFn = Callable[[Path], None]` (`migrations.py:44`) cannot express today. (**Accepted** 2026-07-22; #6; relates #314; companion 0044; follows 0001/0002/0003/0010/0039; constrains `services/migrations.py` before 1.0)
- [0044](0044-snapshot-strip-and-flip-diff.md) — **The snapshot strip is the scrubber's third axis; comparison is a flip, not a split.** The surface for 0043, iterated in a live mockup rather than sketched. **Position is the mode** (0013) — and it governs the strip's *size* too: **compact at rest** (a ruled line under the prose), expanding only when parked, per 0038 §A. **Notches, not beads** (so both axes read apart if they ever share a card); tall+filled = explicit, short+faint = automatic; **Live at the RIGHT end** — deliberately not 0013's home-at-left, where base is *earliest*. **Spacing is the timeline and cannot be linear** — edits cluster, so one old snapshot plus four from this morning would pile the recent four into an unreadable clump; a **log scale** spreads recent and compresses deep history, with `1h/1d/1w` ticks and a minimum gap. **The track never changes width** — notches are % of the track, so anything variable beside it slides every notch (*a timeline that moves when you use it cannot be read*): fixed-width camera, the "as of" label moved to the actions row. **Comparison is a flip, not a split** — two synced panes make the reader do the diffing; flipping one region exploits change-detection and dissolves the sync problem. **One colour rule: the colour says which version the text belongs to** (warm = now, cool = snapshot), so add/delete/modify stop being three cases. **The tint stays in EVERY compare state** — an unmarked single state broke the gesture, because the tint is the *anchor* the words swap underneath. **Inline vs stacked is structural**, never a length threshold (that jitters as you type). **Fields flip, never interleave.** Rendered HTML in 0013's read-only overlay slot, **not** TipTap decorations — the live buffer is never touched, and the layout is trivial in HTML. Two new `--diff-*` triples on **one hue axis (warm ~20° / cool ~205°)** — every other hue is taken, red/green is out on accessibility AND semantics (*before/after*, not *bad/good*), and a warm side drifting to ~350° was rejected on sight as reading like an alarm. **Chroma is HALVED for light** (~15/10 vs ~26/25): the two themes were picked independently by eye and turned out to be the same hues at different chroma, because **a tint on white sits at peak luminance where colour discrimination is best and therefore shouts, while on a dark ground the identical tint barely registers** — so *chroma is not theme-invariant and a merely-inverted palette is wrong in one of the two* (same asymmetry that forced `--accent-emphasis` to exist on the lightness channel). Keys: **←→ = when, A/S/B = which, Esc = live**; **no held modifier** (Shift trips Windows FilterKeys/StickyKeys — and the compare view is read-only, so the whole keyboard is free), auto-repeat must be ignored or the view strobes. **The camera is an affordance, so it is never an annotation** — the design language's own "never both" rule (cf. `⧉`), generalized to the rule that caps the glyph pile-up: **a glyph marks what is true about the VALUE; colour marks what is true about the VIEW** (mutation/override marks are permanent properties; a diff exists only while parked). Tooltip = relative-time ladder + optional description + pinned state; **the empty description is the COMMON case**, so it enriches the date and never replaces it — and its layout is deliberately left to implementation (0005's lesson). (**Accepted** 2026-07-22; #6; companion 0043; follows 0013/0030/0038 §A/0042; mockup at `../mockups/0044-snapshot-strip.html`)

## Post-0.8.0 — Editing infrastructure
- [0050](0050-undo-redo-is-a-caretaker-over-self-reporting-commands.md) — **Undo/redo is a dumb caretaker over self-reporting reversible commands** (not whole-state snapshots). Each actor reports its own reversible change — *palette:* "I created node N"; *node:* "I deleted myself (here is my state)"; *node:* "I spawned an edge to xyz" — so **topology is not a special case** (a deleted node speaks at the instant of death) and "what counts as a change" lives with the node, not a central diff. The **caretaker knows only commands + transaction ids, never nodes/edges** — that ignorance is what lets a **second** node surface (ADR-0048 plot boards) reuse the exact same code with its own command vocabulary; whole-state snapshotting was the beginner's shortcut that stops scaling at two surfaces. **Transactions are an implicit shared-id run** — a cascade (delete → its edges + self) tags its commands with `N`, closed implicitly by the next command without `N`; the common path stays one-command-one-step, no `commit()`. **Commands carry `undo()`/`redo()` closures, in-session only** (uniform with TipTap/CodeMirror, which also die on reload; the data-command path to persistence is named, not built). **No app-wide undo bus** — each surface owns its own caretaker instance, Ctrl+Z scoped to the focused surface, exactly as the prose/code editors already own their library history. Pure rune-store caretaker with a unit test (SvelteFlow is not headless-testable, so the logic must live outside the canvas). Slices: caretaker → the designer emits commands (+ the visible control) → the plot board reuses it unchanged. Rejected: whole-state snapshots, a graph-aware caretaker, an app-wide bus, an explicit transaction framework, serializable/persistent history, extending TipTap/CodeMirror history. - [0059](0059-the-body-is-a-field-and-a-field-gates-ai-authorship.md) — **The body is an intrinsic field, and a field says whether the AI may write it.** A brainstorm-committed lore entry's `body` came back as a verbatim dump of every structured field (a character's `voice`/`physical_appearance` copied whole into the body), which then goes stale on the first field edit and inflates every context assembly that includes the entry — because the body is injected into AI context. **Two root causes, both a field concept handled beside the field model:** (1) `body` is *not a field* — a top-level node attribute with no definition and no **description**, so the commit contract asks for "the complete revised markdown body" (`extraction.py:71`) with nothing saying what belongs in body vs the structured fields, and body never gets the per-field `description` the loop already renders; (2) a field *cannot say the AI must not write it* — writability is one blanket predicate `is_proposable_field` (`entry_patch.py:36`) keyed on id/type/`hidden`, so nothing stopped the brainstorm setting `context_policy: always` (an author-owned cost knob) it didn't understand. **Decision:** `body` becomes an **intrinsic** field (extends 0029 §B) — value in top-level `node.body`, never `metadata.body` (no storage change), injected **only into `has_body` types** (unlike the always-on identity triple), routed to the **body editor** not a rail row (extends 0029 §J), relabel-only, carrying a **description** (single shared built-in, per-*layer* overridable — `FieldOverride` has no `description` aspect) that tells the model what body is *for* — retiring the hardcoded body prose (the dump fix). - [0057](0057-a-conversation-selects-its-lore-once-behind-one-gate.md) — **A conversation's lore is one gated function whose result is dedupped by id.** Lore reaches a chat through **two unreconciled channels** — render-time `relevant_lore()` baked into an **opaque `system_prompt`**, and an **unconditional** send-time `expand_context` — so `context_policy: always` (a *wholesale union*, not a match) is **dropped for every prompt that doesn't call the helper** (the dogfooding symptom: two Always notes never reached a create-character brainstorm), a **deliberately lore-free prompt is impossible** (the send channel injects auto-matched lore regardless), and the same node can be **gathered twice unreconciled** (the backend can't read the opaque prompt to subtract it). The gate signal is **stable-tier state inheriting the existing 1h-cache staleness contract** (not re-agonized). Adjacent, named-not-fixed: `_relevant_lore` leaks `manual_only` via structural refs; the manual picker enforces no policy. - [0061](0061-a-snippet-carries-its-fields.md) — **A snippet carries its fields — inclusion contributes field definitions, not only text.** A prompt's *effective* inputs = its own ∪ the transitive union of `{% import %}`-included snippets' inputs; gathered **statically** from literal include names (runtime conditionals decide execution, never gathering — the inverse of 0057's runtime lore gate); collisions resolve **nearer-wins** (the 0039 schema-inheritance precedent), a same-name/different-type clash surfaced not silenced; **one backend resolver** feeds the invocation dialog, preview, chat inputs strip and editor (one traversal, not four); a `{% import %}` inclusion is a reference edge (0040) so editing a snippet's fields **warns** the prompts/chats that include it. Rejected: re-declare-in-outer (the leak), dynamic gather (the form precedes render), per-surface computation, silent type-coercion. ## 1.0.0 — Character arcs
- [0080](0080-a-character-arc-is-a-plot-subtype-not-a-plotline.md) — **A character arc is a plot subtype, not a plotline** (supersedes ADR-0053 *in part*). ## 1.0.0 — Tags are nodes
- [0082](0082-a-tag-is-a-node-and-a-tags-field-is-a-reference-list.md) — **A tag is a node, and a tags field is a reference list into a vocabulary** (#1778). ADR-0081 exposed that `tags` is a *reference* type modelled as a *value* type: everything that distinguishes it from `list` (the `metadata_refs` traversal, save-time canonicalise + register, a per-layer union-merged registry, rename/merge, scope, colour) is reference behaviour — **minus identity**. A ref stores a machine-minted id and renames free; a tag stores its *name*, so every rename is a rewrite bounded by what the open scope may write (`_reject_sources_above_this_layer` — "the rule, not a stopgap"), and a name-as-id is the **hand-rolled id** the repo already outlawed for nodes (#1716–#1719). The tell: the **one** built-in `tags` field definition (on scene, lore, research AND assistant) resolves against **different vocabularies by kind** (project `tags.yaml` vs machine `assistant-tags.yaml`), the field key + kind pick the store by convention in code, and the stores don't agree on behaviour (canonicalised vs case-sensitive add-only; research notes neither) — so a user-defined `tags` field has undefined semantics. Decision: **a new `tag` kind** (justified on the whitelist test: body-less, picker-minted, machine-layer-resident, hundreds of instances; governance list not document list), class–instance: `tag:base` (fields `color`, `merged_into`) → **a vocabulary = an entry type** (`tag:tag`, `tag:assistant_tag`, user `tag:motifs` via the Custom Data pane) → a tag = one body-less Markdown node in `tags/` (the shape every kind already has; many-per-file rejected). **A tags field = `entity_ref_list`** with `picker_config` naming the vocabulary + one new picker mechanic **`create_missing`** (allowed only for a single concrete entry type; typed name resolved **case-insensitively** across the merged chain before creating; created at the layer the saved node is *written to* — the authoring level when the #339 dropdown is in play, the machine layer for a roster assistant with no project open). The assistant's field is **renamed `assistant_tags`** (one field id = one definition across kinds). **Everything else is the existing ref lifecycle**: rename = edit the title (no propagation, no aliases); backlink edges + usage counts from `edges_by_dst`; purge/heal; search title resolution; `EntryRef` in Jinja; `_partition_entity_ref_list` on promotion (ADR-0078's stay-behind intent preserved by the ref rule); node `color` + ADR-0029 type colour; **scope dropped as stored data** (picker ranking read off backlinks — what auto-broaden approximated); grouping/`overlap` already handle ref lists; the Tags pane becomes the kind's `NodeList`. Layering is node layering (one owning layer, shadow by id — the union merge existed only to reconcile names). **`tagged:` takes an id and means "references this tag"** (a backlink edge exists — schema-free, covers user vocabularies; by-name breaks on rename; parity corpus rewritten). **Merge is a redirect**: rewrite refs in the owned scope, set `merged_into` on the merged-away tag; **the node index is the one choke point** (id lookup canonicalises, edges re-target the survivor — so counts/`tagged:`/titles follow with no consumer work), save-time ref validation rewrites lazily, deleting a survivor **cascades to its redirects**; delete = ordinary node deletion (lossy by design). Migration (v9): a new **`ChainMigration`** step type (root + a context built outermost-first) — per layer: mint nodes from `tags.yaml`, rewrite every `tags`/`assistant_tags` value incl. `overrides/*.md`, `tagged:` leaves in views + chats' persisted picks, the shipped assistant view's on-disk `key: "tags"`, `type: tags` schema fields, `tags` prompt inputs — **the full ladder run on every layer of the declared chain on open, each with its own backup** (load-bearing: dropping `tags` from the type Literal makes an unmigrated ancestor schema fail validation), a **machine-level once step before it** (assistant registry → `tag:assistant_tag` nodes; assistant `tags` → `assistant_tags`; `schema_version` on MachineSettings), scaffold `tags/`. Kind registration follows the `research` trail (NodeFamily + machine families, entry-type upsert whitelist, the three kind ladders + `POST /api/tags`, promotable kinds, frontend kind lists); one file per tag measured at 0.13 ms/file, and a scene save touches no tag file. Front matter stores ids; Jinja `scene.tags` becomes `list[EntryRef]`. Rejected: **identity-by-name + `formerly` aliases** (the first draft — three holes under a parent rename: child/former-name collision, two-layer divergence, every raw-value consumer must resolve), hide-the-type, fold-into-`list`, a `lore:` sub-type (implicit-context/alias/Lore-pane drag; no machine layer), many-per-file YAML, keeping the union registry, `tagged:` by name, merge-by-deletion, a version-dispatching reader. Out: a body on a tag (`lore:` is for prose), target colour on non-tag ref chips, the AI-path join view, auto-deleting merged tags.
